# Domain Docs

This repo is single-context: [GLOSSARY.md](../../GLOSSARY.md) and [docs/adr/](../adr/) at the repo root.

Before exploring the codebase, read the glossary and ADRs relevant to the work. Use the glossary's
terms in issue titles, proposals, hypotheses, and tests. For a missing term, reconsider the wording
or note a real vocabulary gap for `domain-modeling`.

Surface conflicts with accepted ADRs explicitly, naming the decision and why it merits reopening.

If domain docs are absent, proceed silently. `domain-modeling` creates them when terms or decisions
are resolved.
